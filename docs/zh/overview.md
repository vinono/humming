# 架构概览

`humming` 是一个专为 **Bun** 运行时打造、**插件优先** 的轻量级 BFF（Backend For Frontend）内核。

它专为前端工程团队与敏捷平台团队设计，旨在提供一层清晰、透明、具备高度可扩展切面的轻量级服务端能力，而非庞大笨重的企业级全栈框架，亦非底层复杂的全功能 API 网关。

如果您希望以最快的方式了解本项目：

1. 阅读本文：明确架构定位与适用场景
2. 阅读 [插件系统架构指南](./plugin-system.md)：理解可扩展性模型
3. 阅读 [CLI 脚手架指南](./cli.md)：快速初始化新项目

---

## 核心设计摘要

`humming` 内核仅内建三项核心能力：

- **`health`**：健康检查探针与服务就绪检查
- **`options`**：前端数据字典与选项元数据聚合
- **`forward`**：可控的上游 API 代理与流式转发终端

**除上述三项外，所有业务特性均由插件（Plugins）承载。**

这一极简边界是本项目最重要的架构设计准则。

---

## 适用场景与定位

### 推荐使用场景

- **前端团队自控的 BFF 层**：快速聚合接口、处理数据转换与字段清洗。
- **轻量本地路由**：承载前端或业务团队自有的定制接口。
- **数据字典/枚举接口**：高效分发前端所需的静态或远程字典。
- **受控的上游转发**：针对后端微服务提供安全、带熔断重试的透明代理。
- **边缘请求整形**：在靠近用户端处执行 Header 注入、路径重写与协议适配。
- **即插即用的通用切面**：鉴权校验、响应缓存、指标监控、请求限流等功能自由插拔。

### 不适用的场景（非目标）

- **企业级基础设施网关**：如 Kong、APISIX、Traefik、Envoy（humming 运行在其后端，处理业务 BFF 层）。
- **重型领域驱动（DDD）后端框架**：如 NestJS、Spring Boot（humming 倡导极简直观，避免深层 IoC 容器复杂性）。
- **跨部门全局服务治理总线**。

## 核心设计哲学

### 1. 内核极致精简 (Keep Core Small)
内核保持极度克制与透明。当前内核仅包含：
- 请求上下文与统一错误处理
- `GET /health` 健康检查路由
- `GET /api/options` 与 `POST /api/options` 字典路由
- 转发终端与代理执行器
- 插件注册表与运行时共享服务

### 2. 业务与运维能力外推至插件 (Push To Plugins)
所有运维切面与业务逻辑均优先以插件实现：
- 身份认证（JWT / Session）
- 响应缓存（Memory / Redis）
- 跨域策略（CORS）
- Prometheus 监控指标
- 速率限制（Rate Limiting）
- 结构化请求日志
- 业务自定义路由

### 3. 崇尚显式，消除魔法 (Prefer Clarity Over Magic)
`humming` 坚持“代码即文档”的显式风格：
- 显式创建应用实例（`createApp`）
- 显式传入插件列表（无黑盒扫描）
- 显式定义转发规则与匹配前缀
- 显式解析环境变量与类型校验

## 运行时心智模型

系统的运行时执行链路清晰直观：

```text
客户端请求 (Client Request)
  │
  ▼
humming 内核 (Core Runtime)
  ├── 内建路由: GET /health | /api/options | /forward
  ├── 插件路由与全局中间件 (Plugin Routes & Middleware)
  ├── 转发前置/后置钩子 (Forward Hooks)
  └── 传输层执行器 (Transport Executor)
        │
        ▼
  上游服务集群 (Upstream Services)
```

插件系统是系统唯一的扩展接口。内核为插件注入标准上下文：
- `app`：底层 Hono 实例
- `env`：已校验的强类型环境变量
- `logger`：结构化日志器
- `services.options`：字典注册服务
- `services.forwardProxy`：转发钩子注册服务
- `services.localDebugRuntime`：本地联调环境状态注入服务

## 核心优势对比

| 对比维度 | 临时本地开发代理 (如 Webpack/Vite Proxy) | 传统重型后端框架 (如 NestJS) | humming BFF 内核 |
| :--- | :--- | :--- | :--- |
| **运行时稳定性** | 仅供开发调试，无法上生产 | 生产级，但启动慢、内存占用大 | **生产级高并发，微秒级极速响应** |
| **架构心智负担** | 无统一结构，难以扩展中间件 | 大量注解、模块、IoC 容器样板代码 | **显式 TypeScript 函数式装配，零黑盒魔法** |
| **代理转发能力** | 基础 HTTP 转发，无钩子支持 | 需自行基于 Axios/HttpService 封装 | **内建流式代理、KeepAlive、重试与生命周期 Hook** |
| **团队所有权** | 前端配置 | 通常由后端团队主导 | **前端/全栈工程师可轻松自如掌控** |
